# 웹 마피아

Node.js + Express + Socket.IO 로 만든 실시간 웹 마피아 게임입니다. 직업, 타이머, 투표 집계, 채팅 권한은 전부 서버가 판정합니다.
(전체 규칙은 [SPEC.md](SPEC.md) 참고)

## 주요 기능

- 회원가입/로그인 (bcrypt 해시, JWT httpOnly 쿠키), 소켓 연결 시 토큰 검증
- 로비: 방 목록 실시간 갱신, 방 생성(4~12명, 비밀번호, 페이즈 시간, 의사 자기 보호, 마피아 수), 방장 이전, 새로고침 재접속
- 게임: 첫날 낮 토론(투표 없음) → 밤 → 아침 결과 → 낮 토론 → 투표 → 최후 변론 → 찬반 투표 → 승리 판정
- 마피아 수는 방마다 1명 ~ 최대 인원÷3까지 설정 가능. 기본 배분과 다른 판은 랭킹에 반영되지 않습니다(이탈 패널티는 유지).
- 채팅 4채널(public / mafia / dead / system): Socket.IO room 분리 + 서버 발신 권한 검증
- 점수/티어/랭킹: 승패·보너스 점수, 티어, 랭킹 TOP 50, 내 프로필
- 스킨: 모든 화면 상단 선택기로 `기본(누아르)` / `Claude 스타일` / `Mattermost 스타일`을 켜고 끌 수 있습니다(브라우저에 저장). 두 스킨 모두 낮/밤에 맞춰 밝은 톤과 어두운 톤으로 바뀌며, 색·글꼴·레이아웃 느낌만 따라 한 것이고 로고나 이미지는 쓰지 않습니다. (`public/css/skins.css`, `public/js/skin.js`)
- 프로필 사진: 내 프로필에서 사진을 올리거나 기본 아바타로 되돌릴 수 있습니다. 브라우저에서 가운데 정사각형으로 잘라 192×192 JPEG 로 줄여 보내고, 서버는 JPEG/PNG/WebP 만(매직 바이트 검사, 150KB 이하) DB 의 `user_avatars` 테이블에 저장합니다. 방 좌석·랭킹·프로필에 표시됩니다.
- 연출: 직업 카드 플립, 킬/처형/세이브/조사 연출, 낮밤 전환, 종료 컨페티, 레이팅 카운트업 (움직임 줄이기 지원)

## 실행 방법

필요: Node.js 20 이상

```bash
npm install
cp .env.example .env     # JWT_SECRET 을 긴 임의 문자열로 바꾸세요 (없으면 개발용 임시 키로 실행되며 경고가 뜹니다)
npm start                # http://localhost:3000
```

데이터(SQLite)는 `data/mafia.db` 에 저장됩니다. (`DB_PATH` 로 변경 가능)

### 환경 변수

| 이름 | 기본값 | 설명 |
|---|---|---|
| `PORT` | 3000 | 서버 포트 |
| `JWT_SECRET` | (개발용 임시 키) | **운영에서는 반드시 설정** |
| `DB_PATH` | `data/mafia.db` | SQLite 파일 경로 |
| `NODE_ENV` | | `production` 이면 쿠키에 `Secure` 속성이 붙습니다 (HTTPS 필요) |

## 로컬에서 여러 명으로 테스트하는 법

로그인 쿠키는 브라우저 단위로 공유됩니다. 그래서 **같은 브라우저의 탭 여러 개는 같은 계정**이고,
같은 계정으로 새 탭을 열면 이전 탭의 연결은 종료됩니다(한 계정은 한 번에 한 연결만 허용).
서로 다른 플레이어가 필요하면 다음 중 하나를 쓰세요.

- 일반 창 + 시크릿 창 + 다른 브라우저(Chrome / Edge / Firefox)에 각각 다른 계정으로 로그인
- Chrome 프로필을 여러 개 만들어 창을 나눠 띄우기
- `http://localhost:3000` 과 `http://127.0.0.1:3000` 은 쿠키가 따로 저장되어 각각 다른 계정을 쓸 수 있습니다 (총 2명 추가)

게임 시작은 최소 4명이 필요합니다. 사람이 모자라면 시뮬레이션 스크립트나 소켓 클라이언트로 가상 플레이어를 채우세요.
방 만들 때 페이즈 시간을 5초로 줄이면 한 판을 빠르게 확인할 수 있습니다.

## 테스트

```bash
npm test             # 전체 테스트 (아래 시뮬레이션 포함)
npm run simulate     # 가상 플레이어 6명 시뮬레이션만
```

- `test/simulate.js`: 가상 플레이어 6명이 실제 소켓 이벤트로 한 판을 끝까지 진행합니다.
  시민 승리 / 마피아 승리(의사 세이브 포함)를 각각 여러 판 돌리며, 생존자가 dead 채널을 받지 않는지, 시민이 mafia 채널을 받지 않는지,
  사망자가 public 에 쓸 수 없는지를 검증합니다.
- `test/auth.test.js`: 가입/로그인, 비로그인·위조 토큰 소켓 거부
- `test/lobby.test.js`: 방 생성/입장 규칙, 방장 이전, 재접속, 방끼리 상태 분리
- `test/game-start.test.js`: 직업 배분, 직업 비노출, 페이즈 루프, 이탈 처리
- `test/chat.test.js`: 채널별 읽기/쓰기 권한, 히스토리
- `test/night-vote.test.js`: 밤 능력, 투표, 찬반 투표, 승리 조건
- `test/rating.test.js`: 점수 계산, 트랜잭션, 랭킹/프로필 API
- `test/rules.test.js`: 첫날 투표 금지, 마피아 수 설정, 직접 정한 판의 랭킹 미반영
- `test/avatar.test.js`: 프로필 사진 업로드/조회/삭제, 형식·크기·권한 검증, 방 상태·랭킹 반영

## 설정 파일

- `server/config/game.js`: 인원, 페이즈 기본 시간, 직업 배분, 재접속 유예 시간
- `server/config/rating.js`: 승패 점수, 보너스, 이탈 패널티, 어뷰징 기준, 티어 경계

## 구조

```
server/
  index.js          서버 부트(Express + Socket.IO)
  auth/             회원가입/로그인, JWT, 소켓 handshake 인증
  db/               SQLite 접근 코드 (여기만 바꾸면 PostgreSQL 로 교체 가능)
  lobby/            RoomManager (방 목록, 유저↔방 매핑, 재접속 유예)
  game/Game.js      방 1개의 게임 상태·페이즈·판정 (방끼리 상태 공유 없음)
  sockets/          소켓 이벤트 ↔ RoomManager/Game 연결, 채널 room 동기화
  rating/           점수 계산(순수 함수), 티어, 종료 시 반영
  stats/            랭킹/프로필 API
public/             정적 프론트엔드 (바닐라 JS + CSS), img/ 에 SVG
test/               node:test 기반 테스트
```

## 배포 (Render)

> 먼저 알아둘 점: **Vercel 에는 이 서버를 올릴 수 없습니다.** Vercel 은 서버리스라서 Socket.IO 가 쓰는 지속 연결(WebSocket)과
> 서버 메모리의 방/타이머 상태를 유지할 수 없습니다. Render, Railway, Fly.io 처럼 계속 켜져 있는 서버를 쓰세요.

1. 저장소를 GitHub 에 올립니다.
2. Render 대시보드 → **New → Blueprint** 에서 저장소를 연결하면 `render.yaml` 대로 서비스가 만들어집니다.
3. `JWT_SECRET` 은 자동 생성됩니다. 배포 후 `/healthz` 가 `{"ok":true}` 를 돌려주는지 확인합니다.

주의:

- **인스턴스는 1개만** 쓰세요. 방/타이머 상태가 서버 메모리에 있어서 여러 대로 늘리면 방이 서로 보이지 않습니다.
- SQLite 파일은 **영구 디스크가 있어야** 재배포 후에도 남습니다. `render.yaml` 은 디스크가 필요한 `starter` 플랜 기준입니다.
  무료 플랜은 디스크가 없고 일정 시간 요청이 없으면 슬립되어, 재시작할 때마다 계정과 전적이 사라집니다.
- 서버를 재시작하면 진행 중인 게임은 사라집니다(메모리 상태).
- 여러 인스턴스나 무중단 배포가 필요해지면 PostgreSQL(`db/` 교체)과 Socket.IO Redis 어댑터, 방 상태의 외부 저장이 필요합니다.
